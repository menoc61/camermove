    createPayment(input: { bookingId, userId, provider: SupportedProvider, phone?, email?, method?, meta?: Record<string,unknown> }):
    1. Load booking `prisma.booking.findUnique({ where:{ id: bookingId }, include:{ trip:true, payments:true } })`. If null → NotFoundError("Réservation introuvable").
    2. Ownership: if booking.userId !== userId → ForbiddenError("Accès refusé") (no admin bypass for create — only owner pays).
    3. Status guard: if booking.status !== "pending_payment" → ConflictError("Réservation non payable — statut: "+booking.status).
    4. One-pending guard (RESEARCH Pitfall 6): `findPendingPaymentByBookingId(bookingId)` — if exists, return that payment + its authorizationUrl-equivalent without re-calling provider. Also do `prisma.$transaction` check inside create to avoid race: re-query within tx via `SELECT FOR UPDATE` on Booking before insert.
    5. Amount: `amount = booking.totalAmount` (NEVER trust client amount). Validate `currency==="XAF"` hardcoded. For cinetpay: if amount%5!==0 throw BadRequestError("Montant doit être multiple de 5 (XAF)"). Compute description `CamerMove ${booking.reference} Yaoundé→Douala` (use trip data if available, fallback reference).
    6. URLs: `callbackUrl = env.API_URL replaced? Use loadEnv().API_URL or FRONTEND_URL if exists` — fallback to `https://camermove.cm/payment/callback?reference=${booking.reference}`; `notifyUrl = `${env.API_URL}/api/v1/webhooks/${provider}`` (notchpay vs cinetpay distinct per RESEARCH).
    7. Call `getProvider(provider).createPayment({ bookingId, reference: booking.reference, amount, currency:"XAF", email, phone, description, callbackUrl, notifyUrl, channels: methodToChannels(method) })` with helper mapping `mobile_money→MOBILE_MONEY`, `card→CREDIT_CARD`, else `ALL`.
    8. Persist `prisma.payment.create({ data:{ bookingId, provider, providerRef: result.providerRef, amount, currency:"XAF", method: method ?? "mobile_money", status:"pending", webhookPayload: result.rawResponse as any } })` inside same try.
    9. Extend hold if near expiry: if booking.holdExpiresAt < new Date(Date.now()+5*60*1000) then extend to `now + AppSettings.holdExpiryMinutes` via `getAppSettingsCached()` (import). Update booking holdExpiresAt inside transaction.
    10. Audit + metadata: `prisma.auditLog.create({ data:{ actorId:userId, action:"payment.create", entityType:"Payment", entityId: payment.id, metadata: { bookingId, provider, amount, ip: meta?.ip, ua: meta?.userAgent } as never } })` plus `req.log.info` is done in route, but service also logs via injected logger if available.

    12. Return `{ payment, authorizationUrl: result.authorizationUrl }`.
    13. Error paths: provider fetch failure → throw BadRequestError with provider message (500 mapping) but keep payment not created.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→POST /payments | authenticated traveler, untrusted bookingId/provider, idempotencyKey optional but replay stored 24h |
| service→provider API | amount derived server-side, never client amount; XAF + multiple-of-5 enforced |
| service→DB Payment/Booking | ACID guard one-pending-per-booking, status check, ownership check |
| export endpoint → client | RBAC date range injection, large limit abuse |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | Spoofing | POST /payments bookingId of other user | mitigate | service checks booking.userId === auth user, else ForbiddenError 403 |
| T-03-08 | Tampering | Client-supplied amount spoof | mitigate | amount = booking.totalAmount server-side, never req.body amount; XAF hardcoded |
| T-03-09 | Denial of Service | Duplicate POST without Idempotency-Key | mitigate | global idempotencyPlugin caches 24h on Idempotency-Key; plus app guard findPendingPaymentByBookingId returns existing without second provider call |
| T-03-10 | Tampering | Export filter injection (large take) | mitigate | take capped to SEARCH_MAX_LIMIT via loadEnv(), office same as bookings/export |
| T-03-11 | Information Disclosure | GET /payments/:id IDOR | mitigate | getPaymentById checks booking.userId === requester OR role admin/super_admin else 403 |
| T-03-12 | Tampering | CinetPay amount not multiple of 5 | mitigate | service validates amount%5===0 before CinetPay, maps to 400 BAD_REQUEST, never hits provider |
| T-03-SC | Tampering | npm installs | mitigate | no new deps in this plan; if bullmq/ioredis peer needed already approved via 03-RESEARCH audit |

</threat_model>
