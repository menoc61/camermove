<objective>
Foundation for dual-provider payments: DB schema extended for CinetPay, typed env, shared money math, event topics, and provider strategy interface with two raw-fetch adapters + isolated HMAC verifiers. Enables PAY-01 enterprise-grade initiation without SDK lock-in.

Purpose: Without a clean PaymentProvider abstraction and correct crypto helpers, every later route/webhook duplicates provider quirks and invites HMAC / timing-attack bugs. This plan creates the seam that makes NotchPay and CinetPay swappable and testable.

</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API POST /payments | untrusted bookingId/provider/phone, auth required, idempotency replay |
| NotchPay/CinetPay → API webhooks | untrusted raw body + headers, HMAC required, rawBody must not be re-serialized |
| API → NotchPay/CinetPay createPayment | secrets (PUBLIC_KEY, HASH_KEY, CINETPAY_APIKEY/SECRET) leave only via loadEnv(), never logged |
| shared/money → DB | integer math boundary, rounding errors would corrupt ledger |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | POST /payments booking ownership | mitigate | service will verify booking.userId === auth user (next plan), but type system has reference in types |
| T-03-02 | Tampering | Webhook HMAC bypass (parsed body) | mitigate | verify.ts uses rawBody string + timingSafeEqual; adapters delegate, not inline; rawBody captured before JSON.parse (enforced in webhook routes next plan) |
| T-03-03 | Tampering | CinetPay notify treated as truth | mitigate | CinetPayAdapter.verifyPayment does POST /v2/payment/check; service worker must call verify before state transition (next plan) — document contract in adapter JSDoc |
| T-03-04 | Information Disclosure | Secrets in logs | mitigate | No secret logged in adapters/verify.ts; loadEnv() only in factory, never console.log raw env |
| T-03-05 | Denial of Service | Provider fetch timeout | mitigate | AbortController 10s timeout in both adapters; throw to trigger retry/DLQ in worker (not hang) |
| T-03-06 | Tampering | Floating money math ledger drift | mitigate | packages/shared money uses Math.round integer XAF, single source, commission tests compare provider amount vs booking.totalAmount |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS]; RESEARCH flagged notchpay-api SUS + notchpay/cinetpay SLOP — this plan uses 0 new installs, raw fetch; no checkpoint needed but if future install, add checkpoint:human-verify |

</threat_model>
