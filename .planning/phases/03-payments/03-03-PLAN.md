## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider → webhook routes | raw body + HMAC headers, no JWT, must not be rate-limited to 429 that triggers provider DLQ |
| webhook routes → Redis/Kafka | SET NX dedup key 7d, jobId dedup, Kafka at-least-once |
| worker → provider verifyPayment | mutable amount check, must not trust notify amount |
| worker → DB transaction | concurrent expireHolds vs confirm, row locks required |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-13 | Spoofing | Webhook replay (capture valid body+sig) | mitigate | Redis SET NX 7d + DB unique + BullMQ jobId dedup — second delivery returns 200 duplicate, worker guards payment.status===success |
| T-03-14 | Tampering | HMAC via JSON.stringify(parsed) | mitigate | rawBody field from fastify-raw-body used verbatim; verify.ts timingSafeEqual; CinetPay 15-field concat order per docs + fallback |
| T-03-15 | Tampering | CinetPay amount spoof (cpm_amount != booking.totalAmount) | mitigate | worker calls POST /v2/payment/check, checks code 00 + ACCEPTED + amount===booking.totalAmount + currency XAF, else failPayment not success |
| T-03-16 | Tampering | Duplicate commission / double-booked seats on retry | mitigate | Commission.bookingId @unique + guard if status success return + SeatAvailability update under FOR UPDATE, seatsHeld decrement only if >= seatCount |
| T-03-17 | Denial of Service | Webhook handler slow (>10s provider timeout) → retry storm | mitigate | handler does verify→dedup→enqueue→200 only; business tx moved to worker async; handler p99 <100ms |
| T-03-18 | Denial of Service | Stuck pending never recovers (webhook lost) | mitigate | reconciliation job hourly queries pending older than 5m, calls verifyPayment, drives to terminal state |
| T-03-19 | Repudiation | Payment state change not audited | mitigate | each confirm/fail/refund creates AuditLog with actorId system:webhook, provider, reference, deliveryId |
| T-03-20 | Tampering | Seat hold expires races payment success → negative seatsHeld | mitigate | both expireHolds and confirm use SELECT FOR UPDATE on Booking+SeatAvailability inside same transaction, skip if status not pending_payment |
| T-03-SC | Tampering | npm installs | mitigate | only fastify-raw-body may be newly installed — verify before install with `npm view fastify-raw-body version`; keep notchpay-api SUS blocked, raw fetch only |
