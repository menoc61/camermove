## Risks
- qrcode lib availability: verified via npm registry (soldair/node-qrcode, 22M weekly downloads, MIT)
- Ticket.qrDataUrl is a large base64 string (~3-5KB per ticket) — for v1 scale (<10k tickets) this is acceptable; for v2 migrate to object storage
- Email deliverability: MailHog for dev, real SMTP in prod via env
- Twilio sandbox: WhatsApp requires sender approval in production — call out in SUMMARY
- Trip reminder backpressure: 30-min setInterval is fine for v1 scale (<10k bookings/day); BullMQ upgrade path documented in Task 9
