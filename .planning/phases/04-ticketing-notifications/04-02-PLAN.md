  <action>
Create `apps/web/middleware.ts` exporting a `middleware(request: NextRequest)` function and a `config` object. The middleware must:
1. Read the `cm_access` cookie via `request.cookies.get('cm_access')`.
2. If the cookie is absent AND the request path matches one of `/dashboard`, `/dashboard/:path*`, `/tickets/:id` (but NOT `/tickets/lookup`), redirect to `/login?next=<encoded pathname>` via `NextResponse.redirect`.
3. Public paths explicitly excluded (must NOT redirect): `/`, `/results`, `/trips/:path*`, `/book/:path*`, `/tickets/lookup`, `/login`, `/register`, `/auth/:path*`.
4. If the cookie IS present, pass through but set the `x-cm-user-token` request header to the cookie value via `NextResponse.next({ request: { headers: ... } })` so downstream RSCs and route handlers can read it.
5. Do NOT run middleware on `/api/:path*` — API has its own auth. Use `matcher` config to exclude `api/` paths.
6. Export `config = { matcher: ['/dashboard/:path*', '/tickets/:path*'] }` (Next.js will skip `/tickets/lookup` only if we add a negative-lookahead OR we filter inside the function; the matcher approach with internal exclusion is preferred).
   - Note: The user gave specific paths to exclude from middleware redirect. The simplest correct implementation: matcher covers both, and inside the function we explicitly `return NextResponse.next()` for `/tickets/lookup` before checking the cookie.
7. Do not log the token value; only log `requestId` if logging is added (and use the existing logger, not console).
   - The token IS JWT format but we treat it as opaque here; we do not verify signature in middleware (Edge runtime cannot easily use jose + verify + DB lookup cheaply). The actual verification happens in `requireAuth()` on the API side. The middleware is a UX gate, not a security gate. Document this in a header comment.

6. On the initial mount (when zustand rehydrates from localStorage with a stored token), write the cookie too — this handles the case where a user reloaded the page and zustand already has the token but the cookie was cleared (e.g. browser cleared non-HttpOnly cookies on close).
