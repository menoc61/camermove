1. Vue d'ensemble

CamerMove est une plateforme multi-services dediee a la mobilite au Cameroun. Elle connecte les voyageurs aux transporteurs, hotels, loueurs de vehicules et prestataires de services via un seul compte et un systeme de paiement unifie (Mobile Money).

Version

v.0.1-beta (Septembre 2026)

Frontend

Next.js 16, React 19, Tailwind v4, Zustand

Backend

Fastify 5, Prisma 6, PostgreSQL 16, Redis 7

Auth

JWT + Refresh Tokens + RBAC (4 roles)

API Docs

Swagger UI

Services

6 modules operationnels

Acces rapide : Web: http://localhost:3002 • API: http://localhost:3000 • Swagger: http://localhost:3000/docs • Health: http://localhost:3000/health

4. Authentification

Systeme JWT avec 4 roles hierarchiques et refresh tokens securises.

4.1 Roles

RoleNiveauPermissions
voyageur1Reserver, voir ses reservations, payer
partenaire2Gerer ses trajets/hotels/vehicules
admin3Gerer utilisateurs, voir statistiques
super_admin4Acces complet + parametres systeme

4.2 Flux complet

1

Login

POST /auth/login avec email + password. Retourne accessToken (15min) + refreshToken (7j).

2

Stockage

Cookie cm_access (SameSite=Lax, 15min). Zustand store en memoire.

3

Requetes

Header Authorization: Bearer <accessToken> sur chaque appel API.

4

Middleware

Next.js middleware verifie cookie pour routes protegees (/dashboard, /tickets, /admin).

5

API Guard

requireAuth(role?) verifie signature JWT + permissions en base.

6

Refresh

Quand access token expire, POST /auth/refresh avec refreshToken pour en obtenir un nouveau.

4.3 Securite

  • Mots de passe haches avec argon2
  • Tokens JWT signe HS256, expiration 15 min
  • Refresh tokens stockes en DB avec rotation (detection vol)
  • Rate limiting: 5 tentatives/min sur /auth/login
  • Audit logs: toutes les actions sensibles enregistrees
  • Cookie SameSite=Lax (protection CSRF)

5. Workflow de Reservation (Transport)

5.1 Etapes

1

Recherche /results

L'utilisateur saisit origine, destination, date, passagers. Appel API GET /api/v1/search.

2

Liste resultats

Affichage des trajets avec prix, horaires, places dispo. Filtrage client cote client.

3

Detail trajet /trips/:id

Carte des sieges interactive. WebSocket pour mise a jour temps reel des places.

4

Selection siege

Clic sur un siege disponible. Stockage dans Zustand booking store.

5

Informations passager /book/:tripId

Formulaire nom + telephone. Redirection login si non authentifie.

6

Confirmation

API POST /api/v1/bookings cree un hold de 15 min. Evenement Kafka booking.created.

7

Paiement /payments

Choix Orange Money ou MTN MoMo. Appel API POST /api/v1/payments.

8

Confirmation /book/confirmation

Billet QR genere. Evenements payment.completed + ticket.issued.
